Where AWS engineers work vs. what SGLang solves

One Artificial Intelligence (AI) infrastructure stack — two very different problems.

1 · The stack

Bedrock vs SageMaker? Rent the model vs rent the factory.
Which layer is HyperPod? Cluster & systems — the GPU fleet SGLang serves on top of.
Which layer is EC2 UltraServers? Silicon & hardware — cluster-grade fabric inside one box.
Does Anthropic see Bedrock data? No — traffic stays on AWS machines. Full answers in the appendix.

2 · Same stack, two problems

AWS engineers platform · cluster · silicon

  • Fleet economics: placement, quotas, spot across thousands of tenants
  • Elasticity: cold-starting containers, autoscaling
  • Isolation & availability: noisy neighbors, fault domains, Service Level Agreements (SLAs)
  • Plumbing: billing, Identity and Access Management (IAM), observability
  • Unit of optimization: the datacenter

SGLang serving runtime

  • RadixAttention: radix-tree KV cache, automatic prefix reuse
  • Continuous batching; prefill/decode disaggregation
  • Fast constrained decoding: JSON schema, regex, grammar
  • A Domain-Specific Language (DSL) for multi-call Large Language Model (LLM) programs
  • Unit of optimization: one GPU's memory bandwidth

3 · So which one? A worked example

One job: serve Llama-3.1-70B with a shared 10,000-token system prompt to 500 concurrent users.

SGLang-style engineer serving runtime

  • Asks: how do we serve this cheaper and faster?
  • Makes all 500 requests reuse one shared prefix's KV cache (RadixAttention)
  • Tunes the prefill/decode split so time-to-first-token (TTFT) holds under load
  • Profiles kernels to find the memory-bandwidth bottleneck
  • Ships: +40% tokens/sec per GPU

AWS-style engineer platform

  • Asks: how do we deliver this to 500,000 users at 99.9% availability?
  • Places the model on healthy nodes; autoscales replicas on load
  • Isolates tenants, bills per token, survives a zone outage
  • Never touches a kernel
  • Ships: a managed service

Complementary, not competing: you run SGLang on AWS. Bedrock's serving teams optimize kernels too — a 20% fleet-scale throughput gain is margin.

4 · Appendix

Q&A (questions from the review so far)

Q: What is the difference between Amazon Bedrock and SageMaker?

Bedrock — consume: call managed foundation models (Claude, Nova, Llama) through one API; per-token billing. SageMaker — build: full lifecycle for your own models: notebooks, training, inference endpoints. Bedrock = rent the model. SageMaker = rent the factory.

Q: Where does HyperPod fit?

Not the platform layer — it belongs in cluster & systems. Managed GPU clusters (Slurm or Kubernetes) for distributed training: EFA networking, resumable, self-healing. You bring PyTorch/DeepSpeed; HyperPod keeps the cluster alive — a rented supercomputer, sold under the SageMaker umbrella.

Q: So HyperPod is below SGLang?

Yes — the vertical order is a dependency order: upper layers run on top of lower ones. HyperPod is the managed GPU fleet; SGLang serves on top of it. "Below" means foundation, not less important — and SGLang runs on any GPU cluster, HyperPod is just the managed-AWS option.

Q: What are Slurm and NCCL?

Slurm: the job scheduler — which job gets which GPUs, when. NCCL: NVIDIA's communication library — all-reduce group chat averaging gradients between GPUs.

Q: What are PyTorch and DeepSpeed?

PyTorch: Meta's framework — the language you define models in; it runs the math on GPUs. DeepSpeed: Microsoft's engine — ZeRO shards optimizer, gradients, weights across GPUs so big models fit. PyTorch defines the math; DeepSpeed, Slurm, NCCL distribute it.

Q: Why does Bedrock feel like OpenRouter or Perplexity?

Same shape — one API, many models — different layers of this diagram. OpenRouter: reseller router; models run at their original providers. Perplexity: consumer product; model tokens are a cost input (raw material, not product). Bedrock: models run on Amazon's fleet, inside your cloud account.

Q: Does Anthropic see my Bedrock data?

No — requests run on AWS machines; your contract is with Amazon. Anthropic licensed the weights — leased AWS the right to host Claude — and is paid for usage, not your data. That privacy is the enterprise sell: IAM, Virtual Private Cloud (VPC), CloudTrail.

Q: Which layer is EC2 UltraServers?

Silicon & hardware — a giant server of multiple Trainium-based P6 instances with an internal high-speed fabric. Boundary effect: it absorbs what used to be cross-node network traffic into one box.
