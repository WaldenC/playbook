Glossary

Prints cleanly — keep it next to the lessons. Terms are defined the way the lessons use them.

Inference mechanics

Time-to-first-token (TTFT)
Latency from request to the first output token. What a user feels as "the model is thinking."
Tokens per second
Speed of output once the first token has arrived. What a user feels as "reading speed."
Prefill
Phase one of inference: the model reads the whole prompt and produces the first token. Latency grows with prompt length.
Decode
Phase two: the model produces tokens one at a time. Speed is bounded by memory bandwidth.
KV cache
Key-value cache: computed attention state kept per prompt so repeated tokens don't get recomputed. Big for long conversations.
Prompt caching / cachePoint
Marking a stable prefix (like a system prompt) so later calls reuse its computed state instead of re-prefilling. A cache read costs less than a write.
Continuous batching
Serving many requests on one accelerator at once, adding new requests as old ones finish — the standard utilization trick.
Latency-optimized inference
Bedrock per-request flag that routes to a faster serving path, typically at higher per-token cost.

SageMaker mechanics

Cold start
The delay when no warm copy of a model is ready: boot a container, pull the image, load weights, then serve.
Provisioned concurrency
Paying to keep warm copies of a serverless endpoint so requests skip the cold start.
Direct memory access (DMA)
Copying data straight from storage to GPU memory without the CPU or disk in between. How Fast Model Loader streams weights.
Inference component
SageMaker's unit for hosting one model: many components can share one GPU instance, each with its own autoscaling.
Model pinning
Keeping N warm copies of a model to absorb bursts without cold starts.
Managed Spot Training
Training on discount machines AWS may reclaim with ~2 minutes' notice; the platform checkpoints and resumes for you.
Checkpoint
A saved snapshot of training state (weights, optimizer, step) that lets a job resume after interruption instead of restarting.
Checkpointless training
Replicating model state peer-to-peer across nodes so a dead node's replacement gets state from neighbors — recovery in minutes.
Elastic training
Growing a running training job onto extra capacity mid-run while preserving the global batch size.
Deep learning container (DLC)
AWS-maintained container images preloaded with frameworks like vLLM or SGLang.
Bring your own container (BYOC)
Running your own container image on SageMaker instead of a stock one.

UltraServers & silicon

Trainium
AWS's own AI accelerator chip (announced 2023; Trainium2 in 2024, Trainium3 in 2025). No CUDA — it has its own instruction set.
Inferentia
AWS's earlier, inference-focused accelerator family.
UltraServer
An EC2 instance type that fuses multiple physical servers into one: 64 (Trn2) or 144 (Trn3) Trainium chips acting as one accelerator.
NeuronCore
The compute unit inside a Trainium chip. A Trainium2 chip has 8.
NeuronLink
Scale-up interconnect joining chips inside the UltraServer (Trn3 uses the NeuronSwitch-v1 fabric).
Elastic Fabric Adapter (EFA)
Scale-out network between UltraServers across the cluster.
UltraCluster
Networks of tens of thousands of UltraServers joined into one supercomputer.
Neuron SDK
The software stack replacing NVIDIA's: compiler (PyTorch/JAX graphs → Trainium instructions), NeuronX Distributed libraries, NKI.
Neuron Kernel Interface (NKI)
A Python DSL for writing custom compute kernels for Trainium — the escape hatch when the compiler isn't fast enough.
Collective / all-reduce
Patterns for summing or sharing data across chips (gradients in training). Latency per hop matters at rack scale.
High-bandwidth memory (HBM)
Fast memory stacked directly on the chip package. Trn2 UltraServer: ~6 TB; Trn3: 20.7 TB of HBM3e.
PFLOPs (petaflops)
1015 floating-point operations per second. Trn2 UltraServer: 83.2 PFLOPs at FP8.
FP8
8-bit floating-point number format — the precision most modern training and inference peak numbers are quoted in.
Capacity Block
A reserved slice of EC2 capacity (1–64 instances, up to 6 months) so your job doesn't wait on the spot market.

Bedrock & platform

Retrieval-augmented generation (RAG)
Fetching relevant documents at query time and handing them to the model, so answers are grounded in your data.
GraphRAG
RAG over a knowledge graph — good for multi-hop questions where relationships between entities matter.
Guardrail
A policy check in the request path (content filters, topics, PII, image filters) — input side, output side, or both.
AgentCore
Bedrock's managed runtime for AI agents: memory, gateways, identity, observability, code interpreter, browser, evaluations.
Cross-region inference profile
One endpoint that can serve from multiple AWS regions, absorbing local capacity spikes at the cost of network latency.
Intelligent prompt routing
Sending each request to the smallest model that can handle it (Rufus does this at Amazon scale).
Mantle
AWS's internal name for Bedrock's inference engine (appears in job postings; OpenAI-on-Bedrock serves from a bedrock-mantle endpoint).
Batch inference
Cheaper, non-interactive inference for deferrable workloads — roughly half price.

Ops & economics

Spot instance
Spare capacity sold at a discount, reclaimable on short notice. On Trainium, spot can cost MORE than on-demand — scarcity inverts the market.
Autoscaling
Growing or shrinking a fleet automatically from load signals — with cooldowns so it doesn't oscillate.
p95 latency
The latency that 95% of requests beat — the percentile people actually alarm on, because the mean hides tail pain.
Error budget
How much failure a service is allowed in a window (1 − SLO). Teams spend it deliberately.
Tokens per megawatt
Efficiency metric: tokens served per unit of power. The metric of record once data centers are power-limited.
Virtual Private Cloud (VPC)
Your private slice of AWS networking; PrivateLink connects services over it instead of the public internet.
