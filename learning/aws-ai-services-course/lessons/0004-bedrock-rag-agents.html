Beyond the raw API

Bedrock's catalog sells tokens. Real products need more: filtered output, answers grounded in your own documents, and calls to real APIs. This lesson covers the three floors AWS sells above the raw API.

Tokens are the ground floor

Lesson 0002's catalog is the ground floor: a model that answers. Every real application needs more before it ships. Output must be safe, answers must be grounded in documents the model never saw, and sometimes the model must call an API. AWS noticed every customer rebuilding the same plumbing and packaged it as three products: Guardrails, Knowledge Bases, and Agents.

Guardrails: the bodyguard in the request path

Guardrails sit in the request path itself, not as a post-processing step. Content, topic, and personally identifiable information (PII) filters run on the input side before the prompt reaches the model, and again on the output side before the response streams back. AWS claims the multimodal image filters block up to 88% of harmful multimodal content. The same policy is reusable outside Bedrock entirely: the standalone ApplyGuardrail API checks arbitrary text against your policies.

Knowledge Bases: managed retrieval-augmented generation (RAG)

RAG means the model looks up your documents instead of inventing facts. Knowledge Bases automates the whole loop: chunking documents, generating embeddings, storing vectors, and running hybrid search — keyword plus semantic. GraphRAG, general availability (GA) since March 2025, builds a knowledge graph over your data, so multi-hop questions that no single chunk answers can be traced across connected facts. Natural-language-to-SQL completes the set: ask a question, get a query against your own database.

Knowledge Bases and GraphRAG mechanics per the AWS Machine Learning blog — GraphRAG GA announcement.

Agents: models that act

Bedrock Agents gives a model action groups — tools it can call, like a flight-status API — plus knowledge bases to ground itself. AgentCore, GA since October 2025, is the managed runtime behind it: Runtime, Memory, Gateway, Identity, Observability, Code Interpreter, Managed Browser, and Evaluations. The Agent2Agent (A2A) protocol lets agents from different frameworks talk to each other, and policy gates are enforced with automated reasoning — the policy is proven, not hoped for.

Dogfood: Rufus

Amazon's own shopping assistant, Rufus, is the dogfood: 250 million customers in 2025. Its real-time router decides where every prompt goes — complex queries to Claude Sonnet, simple ones to small fast models. That is intelligent prompt routing, the same plumbing this lesson covers, proven at Amazon scale before it was sold to anyone.

Raw tokens are the ground floor. Guardrails, Knowledge Bases, and Agents are the plumbing every real app ends up rebuilding — Bedrock sells the rebuilt version.

Try it

Which floor solves which problem?

A support bot leaks PII in replies and can be prompted into abusive output. Which feature filters the call on both sides?

Guardrails run inside the request path: content, topic, and PII filters on the input side before the prompt reaches the model, and again on the output side before the reply streams back. Knowledge Bases ground answers and caching cuts cost — neither blocks what the model sees or says.

Users expect answers grounded in your own help documents, with citations. Which feature retrieves and answers?

Knowledge Bases is managed retrieval-augmented generation: chunking, embeddings, vector store, hybrid search. Answers cite your documents instead of the model's priors. Guardrails filter but never retrieve, and caching speeds up repeated prefixes without adding your documents to the answer.

A booking bot must call a real flight-status API and answer from the response. Which feature makes a model act?

An agent is a loop: the model decides to call an action group — your flight-status API — reads the result, and keeps going, grounded by a knowledge base. ApplyGuardrail only checks text against policy, and Code Interpreter runs code in a sandbox; neither calls your API.

A question spans many documents — "which shipped orders arrive before Friday?" — and no single chunk answers it. Which capability?

Multi-hop questions cross several documents, so single-chunk vector search falls short. GraphRAG (GA since March 2025) builds a knowledge graph over your data and reasons across connected facts, and natural-language-to-SQL turns such questions into queries against your database.
