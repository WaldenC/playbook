Lesson 0003 · One request

One request, end to end

A Converse call is a pipeline, not a hop: router, guardrail, prefix cache, prefill, decode, stream. Two numbers decide whether it feels fast — time-to-first-token (TTFT) and tokens per second.

The journey

Your app sends one request. A router picks the fastest path for that model and region, then a guardrail checks content, topic, and personally identifiable information (PII) before anything reaches the model. The output gets a second guardrail pass on the way back.

The two numbers SDEs guard

Inference runs in two phases. Prefill reads the whole prompt and produces the first token — its wall-clock time is TTFT. Decode then emits tokens one at a time, bounded by memory bandwidth; its rate is tokens per second. TTFT is the wait; tokens per second is the speed once words start.

The cache moves the boundary. A community benchmark on Llama 3.3 70B measured roughly 80 ms to the first token on a cache hit versus roughly 800 ms on a miss — a 10x gap.

TTFT is a first-class runtime metric in Bedrock — see the runtime metrics docs. Hit-vs-miss benchmark and AWS claims: AWS ML blog on prompt caching.

The number to keep: 80 ms hit, 800 ms miss. A stable prefix is the cheapest TTFT lever you own — no model change, no new endpoint.

Marking the cache point

You mark a cachePoint in the request, usually on the system prompt — the part of the payload that never changes. Reads are up to 90% cheaper than writes, and AWS claims up to 90% cost reduction and 85% TTFT reduction for cached prefixes. Change one word and you've written a new prefix: the cache pays only when the front of your prompt stays stable.

The knobs, and the failure that justified them

Latency-optimized inference is a per-request flag — AWS reports up to 51.65% lower TTFT P50 and 97.1% lower TTFT P90 for Llama 3.1 70B on Trainium 2. Cross-region inference profiles spread your traffic across regions, but geography is priced in: us-east-1 to us-west-2 is roughly 65 ms round-trip; us-east-1 to ap-southeast-1 is roughly 220 ms.

The profiles exist because of one incident. On October 20, 2025, a DynamoDB DNS failure cascaded through us-east-1, and Bedrock's Converse API failed for about 2.5 hours with ConflictException: Lock already in use. Quotas are the last number to respect: Bedrock meters tokens per minute, and output tokens are weighted 5:1.

The engine under all of it is Mantle, Bedrock's multi-tenant serving engine — its SDE postings name vLLM, TensorRT, and Triton as required familiarity, the same serving stack the rest of the industry runs.

Try it

The pipeline, in four questions

Which phase owns time-to-first-token, and which owns tokens per second?

Prefill reads the whole prompt before it can emit anything — that wall-clock time is TTFT. Decode then runs one token at a time, memory-bandwidth-bound, and its rate is tokens per second. The router and guardrail run before either phase and add their own latency.

Your system prompt is long but never changes, and a cachePoint is set. What changes on the next call?

A cache hit skips prefill entirely, so the first token lands fast — the Llama 3.3 70B benchmark shows about 80 ms on a hit versus 800 ms on a miss, and AWS claims up to 85% TTFT reduction. Reads are also up to 90% cheaper than writes. Guardrails still run; only the cache branch is skipped.

Users in Singapore see slow first tokens even on cache hits. What is a real factor?

Round-trip distance is real: us-east-1 to ap-southeast-1 is roughly 220 ms, enough to dwarf even a cache hit's 80 ms first token. Cross-region inference profiles exist to route traffic near users and absorb a regional failure; the ~65 ms pair is us-east-1 to us-west-2.

Your tokens-per-minute quota trips during a long stream. Which usage counts heaviest?

Bedrock meters tokens per minute, and output tokens are weighted 5:1 — every streamed token burns five units against your limit. A long answer can trip a quota that its short question never touched, which is why SDEs watch stream length, not just prompt length.
