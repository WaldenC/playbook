Lesson 0010 · No CUDA, lots of failure

No CUDA, lots of failure

No CUDA. The Neuron SDK is the whole replacement stack — and at 100,000-chip scale, dying nodes stop being an event and become part of the schedule.

The swap: no CUDA

AWS designed the chip, the interconnect, and the network (Elastic Fabric Adapter, EFA) — so the software stack had to be rebuilt in-house too. The Neuron SDK replaces it: a compiler that maps PyTorch and JAX graphs down to Trainium's instruction set, plus NeuronX Distributed, which supplies the tensor, pipeline, data, sequence, and context parallelism libraries. On top, the engines you already know — vLLM, Hugging Face TGI, DeepSpeed, and JAX — run unchanged.

When the compiler can't express an operator efficiently, there's NKI — a Python DSL for writing custom kernels against Trainium's hardware. It's the last-resort layer: start with the compiler, reach for NKI only when profiling demands it.

Stack and flags from the Neuron SDK docs — Trn2 architecture.

Faults are the normal case

At 100,000-chip scale, hardware faults stop being news. The Neuron Distributed Training Library (NDTL) owns checkpointing, and it raised measured cluster uptime from 77.8% to 98.8% — even the after picture means part of the fleet is always recovering.

Checkpoints are tiered: fast local NVMe snapshots roughly every five minutes, with a durable S3 upload every hour. The newer "checkpointless" style replicates state peer-to-peer between live nodes, so a dead node costs minutes of recovery instead of up to an hour of replay.

NDTL uptime numbers via Emergent Mind's Trainium2 paper summary.

The inverted market

Trainium capacity is allocation-controlled. You reserve it through Capacity Blocks — 1–64 instances, up to six months — or through multi-year private agreements, so the leftover spot pool is scarce. Third-party trackers report trn2.48xlarge at about $4.80/hr on demand and $8.60–8.72/hr spot: spot above on-demand.

Pricing per third-party trackers via AI Wiki. Prices are volatile and trackers disagree — re-check AWS pricing pages before relying on them.

What the SDEs do all day

Four problems own the calendar. Collectives: the chips reduce among themselves first — a hierarchical all-reduce down the chip mesh, then across nodes over EFA. Compiler engineering: operator fusion, memory planning between high-bandwidth memory (HBM) and the on-chip scratchpad, quantization, and compilation-time caches so customers don't recompile per boot.

Power and bring-up. One box draws roughly 35–40 kW, and a planned Indiana campus is over 2.2 GW — the metric of record shifted from FLOPs to tokens per megawatt. Every new architecture needs optimization passes: AWS claims GPT-OSS-120B reaches 3x throughput per chip on Trn3.

The flip: Project Rainier brought 500,000 Trainium2 chips online October 29, 2025 — mostly serving inference, with training squeezed into evening hours when inference load drops.

The swap, the faults, the market

A customer's PyTorch training code runs on Trainium unchanged. How?

The Neuron compiler maps PyTorch and JAX graphs to Trainium's own instruction set, so models port without rewrites. NKI exists for the operators the compiler can't express well, and NeuronX Distributed supplies the parallelism libraries underneath.

Your 100K-chip run loses a node every few hours. What is the modern mitigation?

Fault tolerance is tiered: fast local NVMe snapshots every few minutes, a durable S3 upload every hour, and since 2025 checkpointless peer-to-peer state replication that recovers in minutes instead of up to an hour.

Spot price for Trainium runs above on-demand price. What does that tell you?

Capacity Blocks and multi-year agreements lock up most Trainium capacity, so the leftover spot pool is scarce enough to price above on-demand. Read the market: scarcity inverts the usual curve.

Project Rainier launched as a training cluster. By late 2025, what was it mostly doing?

Rainier came online October 29, 2025 with roughly 500,000 Trainium2 chips, and most of them serve inference — training squeezes into the evening hours when inference load drops.
